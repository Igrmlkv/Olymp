# Pre-DPIA: скрининг необходимости оценки воздействия

Статус: черновик. Требует юридической проверки перед публичным релизом.

DPIA обязателен по ст. 35 GDPR при вероятном высоком риске для прав субъектов.
EDPB предлагает 9 критериев; два и более обычно означают необходимость DPIA.
Обязанность зафиксировать вывод существует и при отрицательном результате —
этот документ и есть такая фиксация.

## Оценка по критериям EDPB

| Критерий | Применим | Обоснование |
|---|---|---|
| Оценивание/скоринг | нет | прогресс не покидает устройство, профилирования нет |
| Автоматизированные решения с правовым эффектом | нет | решений о человеке не принимается |
| Систематический мониторинг | нет | нет отслеживания поведения во времени и пространстве |
| Чувствительные данные | нет | не собираются |
| Обработка в крупном масштабе | нет | ожидаемая аудитория — сотни человек |
| Сопоставление наборов данных | нет | наборов данных нет |
| **Уязвимые субъекты (дети)** | **да** | целевая аудитория — дети 10–11 лет |
| Инновационное использование технологий | частично | генерация контента LLM — но контент, а не данные детей |
| Блокирование доступа к услуге | нет | приложение бесплатное и не является условием чего-либо |

Итог: один явный критерий (дети) и один частичный. Полный DPIA не требуется —
при условии, что перечисленные ниже границы сохраняются.

## Границы, на которых держится вывод

Нарушение любой из них делает DPIA обязательным и требует пересмотра документа.

1. Нет аккаунтов, регистрации и логина.
2. Прогресс ребёнка хранится только в IndexedDB на устройстве и не синхронизируется.
3. В промптах к Anthropic нет персональных данных — только тексты задач.
4. Телеметрия не содержит IP, геолокации и свободного текста.
5. `installation_id` случайный и ротируется раз в 30 дней.
6. Ретенция телеметрии — 90 дней.
7. Нет рекламы, трекеров и профилирования.

## Статус телеметрии

Трактуется консервативно как **псевдонимные (то есть персональные) данные**, а не
анонимные. Тесты EDPB на анонимность требуют отрицательного ответа по всем трём:
single-out, linkability, inference. Устройство-скоупный идентификатор не проходит
single-out, даже ротируемый. Поэтому телеметрия описывается в политике
конфиденциальности как обработка персональных данных с правовым основанием
законного интереса (ст. 6(1)(f)) и минимальным объёмом.

CJEU в C-413/23 P подтвердил риск-ориентированный подход: псевдонимизация не делает
данные персональными автоматически, оценка ведётся по разумно вероятным средствам
идентификации. Это аргумент в нашу пользу, но не основание ослаблять режим.

## Cookies

Cookies и трекеров нет, поэтому обязанности cookie-баннера по Telecommunicatiewet
не возникает. Service worker и IndexedDB используются строго функционально —
для офлайн-работы — и согласия не требуют.

## Согласие родителя (ст. 8 GDPR / ст. 5 UAVG)

Возраст цифрового согласия в Нидерландах — 16 лет; страна не снижала его до
допустимых GDPR 13. Для детей младше 16 обработка на основании согласия законна
только при подтверждаемом согласии родителя.

Мы обходим это требование не процедурой, а архитектурой: персональные данные детей
не обрабатываются вовсе. Как только появится серверный профиль, синхронизация
прогресса или сохранение содержимого чата — потребуется и механизм согласия,
и полный DPIA.

## Code voor Kinderrechten

Применимы, в частности: понятный ребёнку язык, минимизация данных, отсутствие
тёмных паттернов и коммерческого давления, возможность удалить данные. Кнопка
полного удаления данных с устройства есть на родительском экране.
