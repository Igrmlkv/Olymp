# CLAUDE.md

Рабочие заметки для Claude Code по этому репозиторию. Полное ТЗ — `docs/spec-v4.md`.

## Что это

Офлайн-first PWA для русскоязычных детей в Нидерландах. MVP — 4 класс РФ, математика
и русский язык, сложность уровня школьного этапа ВсОШ.

## Правила, которые нельзя нарушать

Это не стилистические предпочтения — на них держится правовая модель проекта.

1. **Никаких персональных данных ребёнка на сервере.** Ни аккаунтов, ни логина,
   ни синхронизации прогресса. Прогресс живёт в IndexedDB (`apps/pwa/src/lib/db.ts`).
   Как только появится серверный профиль — DPIA по ст. 35 GDPR становится обязательным.
2. **В промптах к Anthropic — только тексты задач.** У Anthropic нет EU-резидентности
   инференса (`inference_geo` поддерживает только `us`/`global`), и отсутствие ПД
   в промптах — единственное, что закрывает этот разрыв.
3. **Телеметрия без IP и геолокации.** Worker не читает `CF-Connecting-IP`.
   `installation_id` случайный и ротируется раз в 30 дней
   (`INSTALLATION_ID_ROTATION_DAYS` в `packages/schema/src/telemetry.ts`).
4. **Каждая архивная задача несёт атрибуцию и показывает её.** Наличие поля
   проверяет `TaskSchema`, а показ — компонент `TaskStatement`: условие и
   источник рендерятся вместе, поэтому вывести текст без источника нельзя.
   Никогда не рендери `statement_md` напрямую. Опора — право цитирования
   (ст. 15a Auteurswet). См. `docs/legal/attribution.md`.
4a. **Условие архивной задачи не переписывается.** Ни сокращений, ни «улучшений»
   формулировки, ни подгонки под удобный формат ответа. Если задание не влезает
   в `AnswerSchema` — оно не берётся. Свои — только `hints` и `solution_md`.
5. **Ключ Anthropic только в Worker.** Клиент ходит через `/api/*`.
6. **Форматы олимпиады — данные, не код.** Сириус менял максимум с 8 на 56 баллов,
   Москва — с 36 на 41. Всё живёт в `OLYMPIAD_FORMATS`
   (`packages/schema/src/olympiad.ts`), хардкод в UI недопустим.
7. **Русские метки живут рядом с enum'ами, которые их порождают.**
   `SUBJECT_LABELS_RU`, `TOPIC_LABELS_RU`, `STAGE_LABELS_RU`, `GRADE_MAPPING.hint_ru`
   — всё в `packages/schema`, типизировано по enum'у. Новый вариант без метки
   становится ошибкой компиляции, а не строкой `multi_digit` на экране у ребёнка.
   Словарей меток в компонентах быть не должно.

## Язык

Идентификаторы, комментарии и сообщения коммитов — английский. README, документация,
правовые тексты и любые строки UI — русский.

## Схемы — источник истины

`packages/schema` импортируется клиентом, воркером и пайплайном. Любое изменение
формы задачи или пакета начинается там, иначе три потребителя разъедутся.
Там же живут списки, из которых всё выводится: `GRADES`, `MODEL_IDS`,
`TOPICS_BY_SUBJECT`. Повторять их в приложении нельзя.

Контрольная сумма пакета считается в двух местах и обязана совпадать:
`pipeline/src/checksum.ts` и `apps/pwa/src/lib/content.ts`. Меняя одну — меняй обе.

## Конвейер контента

`generate` → `verify` → `publish`. Верификация — независимый прогон того же Opus 5
(не более слабой модели: дешёвый проверяющий просто подтвердит ошибку генератора),
self-consistency из 3 прогонов, спорное уходит к Fable 5.1. Публикуются только задачи
с вердиктом `pass`.

## Разметка условий

`statement_md`, `solution_md` и подсказки — Markdown, и он рендерится через
`react-markdown` с `remark-gfm` (таблицы). Сырой HTML намеренно выключен: пакеты
приходят по сети, а контрольная сумма — не подпись и содержимому доверия не даёт.

Задачам с `choice` и `multi` нужен видимый список вариантов — за это отвечает
`apps/pwa/src/components/AnswerInput.tsx`. Текстовое поле для них не годится.
Имена групп берутся из `useId()`: в режиме олимпиады на странице несколько
задач сразу, и общее `name` склеило бы их радиокнопки в одну группу.

## Навигация по задачам

Адрес задачи — `/{предмет}/{тема}/{id}`. Индекс задачи не хранится в состоянии
компонента: иначе выход из темы сбрасывал бы позицию на первую задачу, а с
сотней задач в теме это делало банк непроходимым. Список темы
(`TaskListScreen`) показывает отметки решённых, читая прогресс одним запросом
`progressFor`, а не построчно.

## Загрузка контента

Экраны берут пакет через хук `usePackage` (`apps/pwa/src/lib/usePackage.ts`),
а не через `getProfile` + `ensurePackage` вручную — иначе обработка ошибки
разъезжается по экранам, и сетевой сбой выглядит как «задач нет».

## Время

Стрики и режим олимпиады работают по `Europe/Amsterdam` (`apps/pwa/src/lib/time.ts`),
не по UTC и не по зоне устройства.

## Проверка

```bash
pnpm typecheck && pnpm test
```

Браузерный прогон — отдельно, потому что ему нужны скачанный Chromium и оба
запущенных сервера (`pnpm dev` и `pnpm dev:proxy`), а в CI ни того, ни другого
нет:

```bash
pnpm exec playwright install chromium   # один раз
pnpm e2e
```

`e2e/tour.spec.ts` проходит оба предмета целиком: первый запуск, список тем,
список задач, решение, отметки, подсказки, разбор, олимпиаду от старта до
результата и рисунки. Каждый тест стартует в браузере без IndexedDB — именно
состояние первого запуска пряталось от нас раньше, когда мы проверяли руками в
своей вкладке с уже выбранным классом и скачанным пакетом. Консоль проверяется
после каждого теста: любая ошибка в ней валит тест. Скриншоты пишутся в
`e2e/screenshots/` (в git не попадают).
